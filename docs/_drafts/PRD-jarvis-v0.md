## 1. 정의

개인 전용 자체 호스팅 팀 메신저. 이 맥에서 서버를 돌리고, 맥·다른 맥·휴대폰 브라우저(PWA)에서 같은 대화와 읽음 상태를 본다. 앱스토어 출시는 하지 않는다.

## 2. 배경

- 영환님은 현재 Slack을 쓰고 있으며, 같은 형태의 메신저를 직접 만들어 보유·통제하고 싶다.
- REA 분석 결과 Slack 데스크톱은 원격 웹앱을 감싼 Electron 셸이어서 구현에 재사용할 것이 거의 없다(D 결론 1). 따라서 공개 개념만으로 새로 만든다(CLEANROOM.md).

## 3. 목표 / 비목표

- 목표 1: 초대된 소수(1–5명)가 채널·DM·스레드로 대화하고, 어느 기기에서든 놓친 대화를 되찾는다.
- 목표 2: 메시지 유실·중복·권한 누출 0건 (B 공통 출시 게이트).
- 비목표: Slack 대체 완성, Slack 데이터 연동, 외부 공개 서비스, 기업 기능(SSO·감사·eDiscovery).

## 4. 원칙

1. 클린룸: Slack 코드·에셋·데이터·룩앤필 미사용 (A 4절, CLEANROOM.md).
2. 서버가 진실의 원천: 기기에 대화 원본을 두지 않는다 (C 3절).
3. 개인 전용 네트워크: 인터넷에 직접 노출하지 않고 Tailscale tailnet 안에서만 접근 (U).
4. 웹 우선: PWA로 시작, 네이티브·데스크톱 셸은 검증 후 (B·U).

## 5. 사용자

- 관리자 1명(영환님): 워크스페이스·초대·채널 관리.
- 멤버 0–4명: 초대받은 사람. 같은 tailnet에 기기를 추가해야 접속 가능 (확인 필요: 다른 사람을 tailnet에 넣을지 — 7-⚖️ 2).

## 6. 핵심 시나리오 (B S1–S5 + U)

| ID | 시나리오 |
|---|---|
| S1 | 초대받아 참여하고, 비활성화되면 즉시 접근이 끊긴다 |
| S2 | 채널에서 한글·링크·코드 블록 메시지를 주고받고 본인 메시지를 수정·삭제한다 |
| S3 | 1:1 DM은 참여자 외 누구도 어떤 경로로도 볼 수 없다 |
| S4 | 스레드에서 멘션을 받고, 읽으면 해제된다 |
| S5 | 연결이 끊겨도 복귀 후 누락·중복 없이 따라잡는다 |
| S6 | 맥에서 읽은 대화가 휴대폰(PWA)에서도 읽음으로 보이고, 휴대폰에서 보낸 메시지가 맥에 1초 안팎으로 나타난다 (U) |

## 8. 명시적 제외

Slack API·실시간 브리지, 멀티 워크스페이스·게스트·외부 조직, 전체 멤버 호출(@channel), 통화·Huddle·영상, 앱 마켓·봇·워크플로·Canvas, SSO/SCIM·감사·eDiscovery, 앱스토어 출시, 네이티브 iOS/Android 앱(검토는 v1 이후).

## 9. 지표

- 파일럿 3개 업무일 동안 S1–S6 수행 성공률 100%, 권한 누출·저장 확인 메시지 유실·복구 중복 0건 (B 게이트 5).
- 저장→상대 표시 p95 (FR-SYNC-01 측정 환경과 함께 기록).

## 10. 계측 이벤트 (본문·이메일 등 PII 미포함)

`message_sent{conv_kind, has_thread}`, `message_ack_latency_ms`, `ws_reconnect{gap_ms, caught_up_count}`, `unread_mismatch_detected`, `auth_denied{route}`. 로컬 로그 파일에만 기록.

## 11. 위험·결정 필요(⚖️)

1. 계정·운영 경계(초대 방식·인증·백업 책임자·삭제 보존) — P1 착수 전 (B 결정 4).
2. 다른 멤버를 내 tailnet에 넣을지(Tailscale 공유 기능 vs 초대) — 멤버 초대 전.
3. 외부 공개로 바뀌면: 개명·약관 원문 확인(A C1–C3) 필수.
4. 맥이 잠자기·종료되면 모든 기기에서 접속 불가 → 상시 구동 필요 시 별도 서버 결정.
