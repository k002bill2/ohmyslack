## 2. 개발설계서 — `docs/04-dev-design/DEV_DESIGN.md`

**점수:** 정확성 3 / 완결성 3 / 문서 간 정합성 3 / 구현 가능성 3

### Must-fix
1. 지정 테스트 파일 경로를 §2의 모노레포 경로와 일치시켜 주세요. 디렉터리 트리는 서버 테스트를 `apps/server/test/`, 웹 테스트를 `apps/web/test/`로 정했지만, 매핑 표는 `server/test/`와 `web/test/`로 표기합니다(43, 53행과 191–207, 210, 215–219행). 현재 표대로면 테스트 작성 위치와 `check:fr-coverage` 대상 경로가 서로 달라질 수 있습니다. 모든 표 경로를 트리 기준으로 고치고 검사 대상과도 대조해 주세요.
2. FR-MSG-02의 지정 테스트가 PRD의 영속성 기준을 검증하도록 보완해 주세요. PRD는 DB 커밋 후 확인 표시와 서버 정상 재시작 후 본문 존재를 요구하지만(PRD 76행), 매핑은 컴포넌트 전송 상태만 지정합니다(201행). 서버 통합 테스트에서 커밋·재시작 후 조회를 검증하거나 기존 통합 테스트를 명시적으로 연결해야 합니다.
3. FR-CLIENT-07 테스트 매핑에 200% 확대와 스레드 닫기 뒤 원래 답글 버튼으로 포커스 복귀를 포함해 주세요. PRD 수용 기준에 두 항목이 있으나(PRD 107행), 지정 테스트 문구는 접근 가능한 이름·가시 포커스·텍스트 상태만 다룹니다(219행). 후자는 디자인 레퍼런스의 키보드 계약에도 있습니다(DESIGN_REFERENCE.md 351행).
4. 재접속 동기화 커서의 범위를 확정해 주세요. 개발설계서는 클라이언트가 보관한 단일 변경 커서로 `/api/sync?since=`를 호출한다고 적었지만(83행), TRD는 변경 로그를 대화별 커서로 저장합니다(TRD 53, 58, 75행). 여러 대화에서 동시에 일어난 변경을 빠짐없이 재생할 수 있도록 계정 전역 커서 또는 대화별 커서 맵을 선택하고 API·저장 위치·재접속 테스트를 정합해야 합니다.

### Should-fix
1. 테스트 표의 “1:1 매핑”은 FR별 지정 테스트 하나라는 뜻인지, 모든 수용 기준을 하나의 테스트 이름에 포함한다는 뜻인지 구분해 주세요(183–189행). 한 FR에 서버·UI·실기기 증거가 함께 필요한 경우 보조 테스트와 수동 증거가 빠지지 않도록 표 구조를 보강하는 편이 좋습니다.
2. WBS·테스트에서 API/WS 이벤트 예시를 TRD와 동일하게 맞춰 주세요. 전송 응답은 `{message_id, seq}`만 적혀 있고(82행), TRD는 `sync_cursor`도 반환합니다(TRD 73행). 읽음 이벤트도 thread 식별 필드가 설계 흐름에 드러나지 않습니다(84행; TRD 92행).
3. P0 통합 테스트용 PostgreSQL 15 및 CI 서비스 컨테이너 전제는 TRD의 현재 확인 필요 항목(실제 PostgreSQL 버전·패키지 버전, TRD 152행)과 조건부로 맞춰 주세요(155, 174행). 확인되지 않은 버전을 확정값으로 고정하기보다 브리프와 실제 환경을 확인한 뒤 정본에 기록해야 합니다.

### 동의하는 강점
- 우선순위 P0와 개발 단계 P0–P4를 분리해 이름 충돌을 줄였고, G0–G4 종료 조건을 제시했습니다(8–15, 90–98행).
- 대화 접근 검사를 단일 함수로 모으고, 커밋 후 WS 전달과 서버 커서 재동기화를 핵심 경계로 뒀습니다(71–84행).

2. PWA 아이콘 요구사항을 TRD와 일치시키거나 TRD가 추가 요구를 받아들이도록 명시해 주세요. 디자인 문서는 `any` 192/512, `maskable`, `monochrome`, 180px Apple touch icon을 요구하지만(407–413행), TRD는 독자 제작 192/512 아이콘만 계약합니다(TRD 127행). 설치 수용 기준과 산출물 수가 달라 구현 완료 판정이 모호합니다.

2. IME 처리에서 compositionend 직후 Enter 1회 무시 규칙은 구체적이지만, Safari 동작 설명을 추정으로 표시한 만큼 실제 지원 브라우저별 QA 결과를 문서의 확인 필요 항목과 연결해 주세요(363–369행).
3. 컴포넌트 오류 상태의 “다시 시도”와 전송 실패 상태의 같은 `client_message_id` 재시도가 어떤 오류에서 가능한지 상태 표에 제한을 적어 주세요(266–267, 300–304행).

### 동의하는 강점
- 반응형 화면을 compact/medium/wide로 나누고, 작은 화면에서 공간→본문→스레드를 라우트로 이동하게 해 PWA 뒤로가기 흐름까지 설명했습니다(245–253, 382–393행).
- 전송·연결 상태 문구, 포커스 복귀, 한글 IME와 실기기 QA 범위를 함께 정의해 PRD 수용 기준을 실제 UI 상태로 연결했습니다(296–369행).

## 4. 문서 간 충돌 목록 (R3 정합 대상)

1. **테스트 파일 경로:** 개발설계서 트리는 `apps/server/test/`와 `apps/web/test/`를 정의하지만(DEV_DESIGN.md 43, 53행), P0 테스트 표는 `server/test/`·`web/test/`로 적습니다(DEV_DESIGN.md 191–207, 215–219행). 표 경로를 트리와 일치시켜야 합니다.
2. **전송 API 응답:** 개발설계서 전송 흐름은 응답 `{message_id, seq}`로 기재합니다(DEV_DESIGN.md 82행). TRD 계약은 `message_id/seq/sync_cursor`를 반환합니다(TRD.md 73행). 메시지 변경 커서의 원자적 기록·응답을 설계 흐름에도 넣어 주세요(TRD.md 53, 58행).
3. **동기화 커서 범위:** 개발설계서는 단일 변경 커서를 클라이언트가 보관하고 `/api/sync?since=`로 조회한다고 적지만(DEV_DESIGN.md 83행), TRD의 `conversation_changes`는 대화별 `sync_cursor`를 사용합니다(TRD.md 53, 58, 75행). 여러 대화의 변경을 한 커서로 누락 없이 따라잡도록 전역 커서 또는 대화별 커서 맵을 선택하고 API·저장 위치·재접속 테스트를 정합해야 합니다.
4. **읽음 이벤트의 스레드 범위:** PRD는 채널과 스레드의 읽음 위치를 분리하고 서버에 저장하도록 요구합니다(PRD.md 91행). TRD의 `read.updated` 필드는 `conversation_id, last_read_seq`뿐입니다(TRD.md 92행). thread별 업데이트라면 `thread_root_id` 또는 동등한 식별 정보가 이벤트에 필요합니다. 개발설계서의 읽음 흐름도 이 이벤트를 fan-out한다고만 적습니다(DEV_DESIGN.md 84행).
5. **PWA 아이콘 세트:** TRD는 독자 제작 192/512 아이콘을 적고(TRD.md 127행), 디자인 레퍼런스는 maskable·monochrome·Apple 180px까지 요구합니다(DESIGN_REFERENCE.md 407–413행). MVP 설치 게이트에 필요한 필수 세트를 합의해야 합니다.
6. **다크 모드 결정:** 디자인 레퍼런스는 자동 라이트/다크 지원을 요구하면서 7절에서 자동 전환을 적지만(DESIGN_REFERENCE.md 374행), 14절에서는 MVP 여부를 미결정으로 남깁니다(DESIGN_REFERENCE.md 515행). 문서 내부 결정 충돌로 R3에서 단일화가 필요합니다.
7. **삭제 후 동기화 재생:** PRD는 삭제 본문을 복구 응답에서도 제거하라고 요구합니다(PRD.md 79행). TRD는 변경 로그에 `snapshot`을 저장하고 삭제도 cursor 순으로 재생하는데(TRD.md 53, 58, 75행), 과거 수정 snapshot의 본문이 이후 삭제 상태에서도 재생될 수 있는지 제한을 두지 않았습니다. 삭제 뒤 모든 catch-up/snapshot 응답에서 본문과 멘션이 제거되는 보장을 명시해야 합니다.
