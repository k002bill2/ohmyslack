## 1. 정의

영환님 개인 전용으로 사용하는 자체 호스팅 웹 메신저입니다. 이 맥의 서버를 원장으로 삼고, 맥·다른 맥·휴대폰 브라우저(PWA)에서 같은 대화와 읽음 상태를 봅니다. 접속은 본인 tailnet 기기로 제한하며 앱스토어 출시는 하지 않습니다.

## 2. 배경

- 영환님은 현재 Slack을 쓰고 있으며, 일반 메신저 개념을 바탕으로 직접 만들어 보유·통제하려는 목적입니다(J·B).
- 합본 2–3절은 데스크톱 분석과 독립 제품 구현을 구분하며 Slack.app 추가 분석 종료를 기록합니다. 구현은 공개 일반 개념과 독자 에셋으로 진행합니다(CR 1–3·6절).

## 3. 목표 / 비목표

- 목표 1: 영환님이 개인 대화를 채널·DM·스레드로 관리하고 어느 본인 기기에서든 놓친 대화를 되찾습니다. 초대·DM 기능은 유지하되 복수 계정 검증은 합성 계정으로 합니다. 타인 사용은 별도 승인 전제입니다.
- 목표 2: 메시지 유실·중복·권한 누출 0건 (B 공통 출시 게이트).
- 목표 3: 영환님이 Hermes 에이전트 Jarvis와 대화하고(지시·진행·결과), 정기 브리핑(텍스트·음성)을 받고, 명령 승인을 처리하는 일을 Slack 없이 이 앱에서 합니다(U 2026-11-08, ADR-001).
- 비목표: Slack 대체 완성(단, Jarvis 대화·브리핑 수신은 목표 3), Slack 데이터 연동, 외부 공개 서비스, 기업 기능(SSO·감사·eDiscovery).

## 4. 원칙

1. 클린룸: Slack 코드·에셋·데이터·룩앤필 미사용 (A 4절, CLEANROOM.md).
2. 서버가 진실의 원천: 기기의 화면 메모리는 일시적 사본이며, 서버 저장 확인이 영속성 기준입니다. P0에서는 대화 본문을 지속 캐시에 저장하지 않습니다(U2·C).
3. 개인 전용 네트워크: 인터넷에 직접 노출하지 않고 Tailscale tailnet 안에서만 접근 (U).
4. 웹 우선: PWA로 시작, 네이티브·데스크톱 셸은 검증 후 (B·U).

## 5. 사용자

- 실제 사용자·관리자: 영환님 1명입니다. 본인 기기 여러 대가 같은 앱 계정으로 로그인합니다. Tailscale 접속 자격과 앱 로그인은 별개입니다.
- 초대·1:1 DM·권한 경계 검증: 격리된 테스트 환경에서 관리자 A, 멤버 B, 비참여자 C의 합성 계정을 씁니다. 실제 타인 초대나 tailnet 멤버 추가를 이 PRD가 승인하지 않습니다.
- 초기 관리자 생성은 §7-7의 운영 런북 항목으로 관리하며 별도 FR을 추가하지 않습니다. 인증·복구 구현의 정본은 TRD §5입니다. 공개 가입·외부 이메일 발송 서비스는 요구하지 않습니다.
- **봇 계정**: Hermes 게이트웨이가 쓰는 비인간 계정 1개(Jarvis). owner가 로컬 명령으로만 만들고 폐기합니다. 사람 로그인은 불가능하며 사용자 수(1명) 계산에 들지 않습니다(§7-8, ADR-001).

### 7-7. 읽음·이력·운영의 제품 계약

#### 스레드 unread 대상과 집계 (FR-SYNC-03/04/05의 정본)

- 현재 접근 가능한 대화에서 **원문을 작성했거나, 답글을 작성했거나, 멘션을 받은 스레드**만 개인 스레드 unread 대상입니다. 단순히 열어 본 것만으로 새 구독 대상이 되지는 않습니다. 자격 발생 이후 멘션/답글이 수정·삭제되어도 대상 자격은 유지하며 대화 접근 권한 상실 시 표시·집계에서 제외합니다. 수동 팔로우/해제 기능은 MVP에 넣지 않습니다.
- 해당 스레드에서 한 번도 읽지 않았다면, 대화 참여 이후의 접근 가능한 미열람 답글을 모두 집계합니다(대상 자격이 생기기 전 답글도 포함). 자기 답글·삭제 답글은 제외합니다. 대상이 아닌 스레드는 새 답글 배지를 올리지 않으며, 직접 열어 읽으면 해당 읽음 위치만 저장합니다.
- 본문 unread는 원문만, 스레드 unread는 대상 스레드의 답글만 셉니다. 스레드 unread를 본문 unread 숫자에 합산하지 않습니다. 멘션 수는 접근 가능한 미열람 원문/답글의 자기 대상 멘션 수이며 자기 발신·삭제·중복을 제외합니다. 사이드바 강조·숫자·점·문구는 디자인 레퍼런스 §6의 정본을 따르되 이 집계 의미를 바꾸지 않습니다.
- 실제 열람은 인증된 앱이 전경이고 해당 본문/스레드가 열린 상태에서, 목표 위치까지 접근 가능한 메시지가 누락 없이 로드되어 화면에 표시된 경우입니다. 백그라운드 수신·미개봉 스레드·단순 페이지 다운로드는 읽음이 아닙니다. 커서 유효 범위·비연속 seq 처리·서버 병합은 TRD §2–4 정본을 따릅니다. 더 오래된 페이지를 다시 열어도 이미 저장한 읽음을 후퇴시키지 않습니다.
- 합성 A/B/C로 '무관한 스레드→답글 배지 없음', '원문/답글 작성·멘션으로 대상 편입', '최초 편입의 이전 미열람 답글 집계', '본문 열어도 답글 배지 유지', '답글 열람 시 두 기기 동시 해제', '멘션 수정·삭제와 자기 메시지 제외'를 검증합니다.

#### 원문·답글 이력과 상한 (FR-MSG-01/04/06)

본문 이력의 한 페이지는 원문 수를 기준으로 채우며 답글을 섞어 페이지 크기를 소모하지 않습니다. 답글은 원문별 이력에서 탐색합니다. 삭제 자리표시자는 각 이력의 정렬 위치를 유지합니다. 답글이 대화 공통 seq를 소비하는지, 페이지 커서/limit·응답 스키마·API 이름은 **정본: TRD §2–4**를 인용하며 PRD가 별도 저장 계약을 만들지 않습니다. 원문 seq 사이의 답글/삭제로 인한 숫자 간격을 메시지 유실로 판정하지 않습니다.

본문 길이 단위·상한, HTTP/WS 크기, 로그인 횟수·관찰/차단 기간·정상 복구 조건, 세션 수명/연장 규칙은 **정본: TRD §3·5**입니다. 개발 시 테스트 입력은 해당 정본의 수치를 읽어 상한/상한+1, 허용 횟수/초과 1회, 차단 만료 전/후로 판정합니다. R3 브리프 §2에 따라 PRD에 임시 숫자를 중복 기입하지 않습니다. TRD 최종안에도 값이 없으면 ⚖️ 미정합으로 남기고 해당 FR은 구현 준비 완료로 판정하지 않습니다.

#### 초기 관리자·복구 — 운영 런북 항목 (별도 FR 아님)

첫 관리자 생성은 공개 가입 기능이 아니라 **초대 기능을 시작하기 위한 초기 운영 전제**입니다. 별도 FR-AUTH-07을 신설하지 않고, FR-AUTH-01의 검증 선행 조건 및 개발설계서의 준비/인증 WBS에 연결합니다. 로컬 운영 절차로만 최초 관리자 1명을 생성하고, 이미 존재하면 재생성·덮어쓰기를 거부하며, 원격 공개 관리자 가입 경로를 제공하지 않아야 합니다. 명령·인증/복구 방식은 TRD §5 정본, 런북·담당·시험 증거·종료 게이트는 개발설계서 §3–6 정본입니다. 이는 현재 라운드에서 계정 생성이나 DB 접속을 승인하는 뜻이 아닙니다.

초기 검증은 빈 합성 환경에서 최초 생성 성공→재실행 거부→비관리자 원격 생성 거부→FR-AUTH-01 초대 시작을 하나의 운영 증거로 남깁니다. 이 증거가 없으면 초대 시나리오 S1 준비 완료로 보지 않습니다. 자격 증명 복구 후 기존 세션 처리·만료는 TRD 정본으로 시험하며 본인 유효 세션의 정상 PWA 재개에 반복 비밀번호 입력을 강제하지 않습니다.

## 9. 지표·파일럿 수용 게이트

모든 수치는 **제안 목표이며 미측정**입니다. 실제 제품 가용성·성능 보장은 아닙니다.

1. 영환님 혼자 본인 맥·휴대폰 2대 이상으로 3개 업무일 동안 S2·S4·S5·S6를 수행합니다. S1·S3는 격리된 합성 A/B/C로 검증합니다. 각 시나리오 성공 100%, 권한 누출·저장 확인 메시지 유실·재시도 중복은 0건이어야 합니다.
2. 연결 20개·5msg/s·10분 합성 부하에서 FR-SYNC-01 목표를 평가합니다. 서버/기기/브라우저 버전·tailnet 경로·실패율·표본 수·지연 p50/p95를 함께 기록합니다. 서로 다른 기기 시계 오차를 교정하거나 동일 시계 관측으로 측정합니다.
3. 다기기 읽음 수렴은 FR-SYNC-04/06, 모바일 재개·변경 복구는 FR-SYNC-02/07로 별도 판정합니다. 백그라운드 실시간 수신은 요구하지 않습니다. 푸시 수신은 FR-CLIENT-05와 S8로 판정합니다.
4. 모든 P0 FR별 테스트 증거가 있어야 MVP 게이트를 통과합니다. 검증 누락은 통과로 보지 않습니다. 파일·검색·외부 알림 부재로 일상 사용을 완료하지 못하면 실패 사례를 기록해 v1 우선순위를 재결정합니다.
5. FR-OPS-02의 격리 복원 대조와 FR-OPS-01의 노출 경계 검증을 완료해야 개인 사용을 시작합니다. 이 문서 작성은 해당 실행 승인이 아닙니다.
6. **Slack 전환 판정(H4)**: Slack과 병행 7일 동안 브리핑 수신 유실 0건, Jarvis 대화 스레드 세션 이어짐 실패 0건, 승인 왕복 성공, iPhone 알림 수신 기록. 판정·전환 실행은 영환님(ADR-001 §7).

## 10. 계측 — 개인정보 없는 허용 목록

외부 분석 SDK·원격 전송을 쓰지 않습니다. 로컬에서 아래 고정 필드만 수집합니다. 본문·초안·이메일·표시 이름·IP·User-Agent·계정/기기/세션/메시지/대화 ID·URL/쿼리·초대 링크·쿠키·토큰·원시 오류/스택은 계측 필드로 넣지 않습니다. 식별자 해시도 넣지 않습니다.

| 이벤트 | 허용 필드 | 목적 |
|---|---|---|
| message_send_result | outcome enum, conv_kind enum, has_thread boolean, duration_ms bucket | 전송 실패·중복·지연 집계 |
| sync_result | trigger enum, outcome enum, caught_up_count bucket, duration_ms bucket | 재접속·전경 복귀 수렴 확인 |
| read_sync_result | outcome enum, duration_ms bucket | 읽음 상태 불일치 횟수 |
| auth_denied | action enum, reason enum, count | 접근 거부 확인; 원시 URL 미사용 |
| client_state | state enum, count | 연결 끊김·복귀 오류 집계 |
| bot_delivery_result | direction enum{in,out}, outcome enum, has_attachment boolean, duration_ms bucket | 봇 송수신 유실·지연 집계(§9 게이트 6); 식별자·본문 미기록 |

- 허용 필드 밖 값은 기록하지 않습니다. 임의 문자열 대신 사전 정의 enum·구간값을 사용합니다. 일 단위 집계, 최대 7일 로컬 보관을 R1 가정으로 제안합니다.
- 단순 지연 계측용 클라이언트 메모리 상관 값은 디스크에 기록하지 않습니다. 세밀한 성능 수치는 합성 테스트에서만 별도 결과로 남깁니다.
- 이벤트·필드명은 TRD와 개발설계서 합의 전 가정입니다. FR-OPS-03으로 누출 부재를 검증하며, 계측 실패가 전송 실패를 만들지 않아야 합니다.

### 사실 / 추정 / 확인 필요

- **사실(문서 대조):** R2의 PRD Must-fix는 Opus M-P1–3·Fable P-1–3으로 6건이며 Luna는 0건입니다. FR 50개/P0 42개(기존 42/33 + 신규 FR-BOT-01–06·FR-MSG-10(P0)·FR-OPS-09(P1) + 승격 FR-CLIENT-05·FR-OPS-05: P0 33+6+1+2=42)와 S1–S8입니다(v1.3, ADR-001). 제품 구현·성능·보안 테스트를 실행하지 않았습니다.
- **설계 제안:** 스레드 대상 자격·최초 unread·원문 전용 페이지·초기 관리자 운영 전제는 R3 제품 수용 계약입니다. 성능 목표·개인정보 없는 계측·본문 지속 캐시 금지도 미측정 요구사항입니다.

### 정본·변경 관리 계약

1. FR 표는 **5열(ID / 요구사항 / 우선순위 / 수용 기준 / 출처)** 순서와 `FR-AREA-nn`, `P0/P1/P2` 표기를 유지합니다. 기존 ID의 의미·우선순위·수용 기준을 바꾸면 PRD 변경 이력과 개발설계서 FR→테스트 매핑을 함께 정합합니다. v1.3(ADR-001)에서 BOT 영역 신설 및 승격으로 FR 50개/P0 42개가 됩니다. v1.4(BOT_CHANNEL_SPEC)에서 P1 FR FR-BOT-08–11을 더해 FR 54개/P0 42개가 됩니다(P0 불변이므로 6-2 매핑 변경 없음). 개발설계서 6-2 매핑을 같은 변경에서 갱신합니다.
2. 테이블·컬럼·API·WS·커서/seq·인증·응답 코드·보안은 **TRD §2–5 정본**입니다. 상태 코드 자체를 제품 FR에 중복 고정하지 않습니다. 참여 비작성자·비참여자·비관리자·비활성 사용자의 거부 효과는 FR로 검증하며 상태 코드는 정본 표를 사용합니다.
3. 브레이크포인트·폭·컴포넌트·상태 문구·키맵·IME·아이콘은 **디자인 레퍼런스 §5–9 정본**입니다. 모바일/중간 폭/데스크톱 모든 정본 구간에서 FR-CLIENT-01/02를 검증합니다. 다크 모드 등 외관 선택은 그 문서의 채택값을 따릅니다.
4. 저장소 구조·WBS·준비/개인 사용 게이트·FR 매핑·CI·테스트 DB는 **개발설계서 §2–6 정본**입니다. 초기 관리자 운영 증거는 별도 FR 신설 대신 그 문서의 런북 게이트로 추적합니다. 계측 의미·허용 키의 정본은 본 PRD §10입니다.
5. P0/P1/P2는 기능 우선순위이고 개발 단계 P0–P4와 다릅니다. P0=MVP 필수, P1=v1 선택, P2=후속 별도 승인 후보입니다. Electron·export는 개발설계서의 후속 단계로만 검토합니다. 정본 간 의견 차이는 교차 수정하지 않고 `⚖️ 미정합 — 상대 문서 file:line`으로 표시합니다.
